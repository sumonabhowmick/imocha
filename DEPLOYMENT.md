# Deploying AssessFlow AI (free)

AssessFlow AI runs as **one web service on Render** (API + admin console + student portal),
with the database on **Neon** and email through **Brevo**. All three have free plans and
need no credit card.

| Part | Service | Why |
|---|---|---|
| App | [Render](https://render.com) free web service | Runs FastAPI as-is, with automatic HTTPS (browsers only allow the webcam on HTTPS sites) |
| Database | [Neon](https://neon.tech) free PostgreSQL | Does not expire (Render's free database is deleted after about 30 days) |
| Email | [Brevo](https://www.brevo.com) free plan | Sends over HTTPS; free hosting plans usually block Gmail's SMTP ports |

Never upload `.env`. Secrets are typed into each service's settings page.

---

## 1. Neon: create the database

1. Sign up at https://neon.tech (GitHub sign-in works).
2. **Create project**: name `assessflow`, region **AWS Asia Pacific (Singapore)**, choose the **newest Postgres version** offered.
3. Create a database named **`assessflow_ai`** (Dashboard → Databases → New database). The migration safety check only accepts names starting with `assessflow`.
4. Click **Connect**, pick database `assessflow_ai`, **turn off "Connection pooling"**, and copy the connection string:
   `postgresql://USER:PASSWORD@ep-xxxx.ap-southeast-1.aws.neon.tech/assessflow_ai?sslmode=require`

### Copy your local data into Neon (optional)

Put the Neon string into your local `.env` on a new line (this file never leaves your PC):

```
NEON_DATABASE_URL=postgresql://USER:PASSWORD@ep-xxxx.ap-southeast-1.aws.neon.tech/assessflow_ai?sslmode=require
```

Then copy the whole local database (tables, data and migration version) into the empty Neon database:

```powershell
$env:PGPASSWORD = ""   # pg_dump asks for the local password
& "C:\Program Files\PostgreSQL\18\bin\pg_dump.exe" --no-owner --no-privileges -U postgres -h localhost assessflow_ai -f assessflow_ai.sql
& "C:\Program Files\PostgreSQL\18\bin\psql.exe" "<NEON connection string>" -v ON_ERROR_STOP=1 -f assessflow_ai.sql
Remove-Item assessflow_ai.sql
```

Skip this to start with an empty database; Render's build then creates the tables.

## 2. Brevo: email

1. Sign up at https://www.brevo.com (free plan).
2. **Senders, Domains & Dedicated IPs → Senders → Add a sender**: your Gmail address. Open the verification email Brevo sends and confirm.
3. **SMTP & API → API Keys → Generate a new API key**. Copy it (it starts with `xkeysib-`).

Emails sent "from" a Gmail address through Brevo can land in Spam at first; mark them "Not spam".

## 3. Render: the app

1. Sign up at https://render.com with **GitHub**, and allow access to the repository.
2. **New → Blueprint**, choose this repository. Render reads `render.yaml` and proposes the service **assessflow-ai**.
3. Fill in the values it asks for:

| Key | Value |
|---|---|
| `DATABASE_URL` | the Neon connection string |
| `PUBLIC_BASE_URL` | `https://assessflow-ai.onrender.com` (change it later if Render gives the service a different address) |
| `DASHBOARD_URL` | the same address followed by `/admin` |
| `OPENAI_API_KEY` | your OpenAI key |
| `BREVO_API_KEY` | the Brevo key |
| `SMTP_FROM_EMAIL` | the Gmail address you verified in Brevo |
| `ADMIN_NOTIFICATION_EMAIL` | where "result ready" notices go (can be the same Gmail) |

`APP_SECRET_KEY` is generated by Render automatically. Keep it: changing it invalidates invitation links and codes that were already sent.

4. **Apply**. The build installs packages and runs `alembic upgrade head`. When it finishes, open
   `https://<your-service>.onrender.com/api/health`. You should see `"status":"ok","database":"ok","ai_configured":true,"email_backend":"brevo"`.
5. If Render chose a different address than `assessflow-ai.onrender.com`, update `PUBLIC_BASE_URL` and `DASHBOARD_URL` under **Environment** and save (it redeploys). Invitation links are built from `PUBLIC_BASE_URL`.

## 4. Admin account

If you copied your data, your existing admins already work. Otherwise (or to reset a password)
run these from your PC against the Neon database:

```powershell
$env:DATABASE_URL = "<NEON connection string>"
.venv\Scripts\python -m scripts.create_admin --name "Your Name" --email you@gmail.com
# or: .venv\Scripts\python -m scripts.reset_admin_password --email you@gmail.com
Remove-Item Env:DATABASE_URL
```

## 5. Check everything

1. Open the site → **Admin** → sign in.
2. Add yourself as a candidate, assign an assessment and send the invitation.
3. From the email, open **Start Assessment**, enter the code, allow the camera, take the test and submit.
4. Within a minute or two you should receive the result email; the admin console shows the result, AI feedback and proctoring timeline.

## Free-plan limits

- **Sleeping:** the service sleeps after about 15 minutes without visitors; the next visit takes about a minute. Open the site a few minutes before a demo or exam.
- **While asleep:** reminder emails and auto-submission of expired tests wait until the next visit. Expired attempts are still finalised as soon as anyone opens them, and scores are never affected.
- **AI assistant approvals** waiting for a decision are lost when the service restarts or sleeps; ask again.
- **Brevo free:** about 300 emails per day.
- For real exams with many students, use Render's paid Starter plan so the service never sleeps.

## Updating

Commit and push to `main`. Render redeploys automatically and applies new migrations during the build.
